# memory-lancedb-dreaming v0.3.11 小泡验收步骤

> 待测包：`memory-lancedb-dreaming-0.3.11.tgz`  
> 目标环境：OpenClaw 2026.7.1（最低支持 2026.6.9）  
> 本轮只做本地安装验收，不发布 ClawHub。

## 1. 安装前记录

```bash
openclaw --version
node --version
openclaw memory status --deep
```

备份 `~/.openclaw/openclaw.json`、现有插件目录和 workspace 中的
`MEMORY.md`、`DREAMS.md`、`memory/.dreams/`。

## 2. 安装待测包

```bash
openclaw plugins install ./memory-lancedb-dreaming-0.3.11.tgz
openclaw gateway restart
```

若当前 OpenClaw 不支持本地 tgz 安装，解压后放到
`~/.openclaw/plugins/memory-lancedb-dreaming/`，在该目录执行
`npm install --omit=dev`，然后重启 Gateway。

## 3. 基础检查

调用：

- `dreaming_status`
- `dreaming_doctor`

必须满足：

- version 为 `0.3.11`
- LanceDB plugin id/path/dimensions 正确
- doctor 无 `fail`
- Gateway 日志无 plugin load error、重复 cron、未处理异常

## 4. Cron 迁移检查

两条托管 cron 都应为：

- `sessionTarget: isolated`
- `payload.kind: agentTurn`
- 不带 `cron.delivery`

从旧版升级时，原 `main + systemEvent` job 应被原地更新。若有一个改过名字、
但 payload 仍含 `__openclaw_memory_lancedb_dreaming_trigger__` 的旧 job，应被清理，
最终每类托管 cron 只保留一条。

## 5. 全流程检查

调用 `dreaming_trigger`，参数 `phase=all`。检查：

- Light / REM / Deep 均完成
- `dreaming_status.lastRunResult` 正常
- `DREAMS.md`、阶段报告、日报和 snapshot 可读且没有半截内容
- `MEMORY.md` 仅在满足 Deep 门槛时追加 promotion
- 日报配置了 delivery 时只推送一次；`pushOn=changed` 时无变化不重复推送

## 6. 并发与配置刷新

1. 在 Dreaming 仍运行时触发日报，后者应返回/记录 `pipeline busy`，不得并发写文件。
2. 修改活动 LanceDB slot 的 `dbPath` 或 dimensions 后，再触发 Dreaming；日志应显示
   使用新配置。生产环境仍建议修改配置后重启 Gateway。

## 7. 回传内容

请回传：

- `openclaw --version`、Node 版本
- `dreaming_status` 与 `dreaming_doctor`
- 两条 cron 的 sessionTarget / payload.kind
- 本次 Light / REM / Deep / promoted / narrative 结果
- Gateway 中与 `memory-lancedb-dreaming` 有关的 warning/error

验收通过后再统一提交 GitHub、打 `v0.3.11` tag，并使用该真实 commit 做
ClawHub dry-run/正式发布。
